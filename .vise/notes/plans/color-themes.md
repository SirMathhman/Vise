## Plan: Color Themes (Forest, Volcano, Underwater)

Add three named dark-variant themes to the web UI. Each is a full colour palette (dark-based, with its own accent hue) applied via a `data-theme` attribute on `<html>`, exactly like the existing light theme. "Match system" and the existing Light/Dark remain unchanged.

**Why:** the current system supports only Light/Dark/System; a small set of named themes gives the user distinct visual palettes without a theme editor.

**Steps**

### Phase 1 — Core type and resolution logic

1. **`web/src/status/theme-choice.ts`** — widen `ThemeChoice` and `resolveTheme`: - Change the `ThemeChoice` type union from `"system" | "light" | "dark"` to `"system" | "light" | "dark" | "forest" | "volcano" | "underwater"`. - Add a `ResolvedTheme` type: `"light" | "dark" | "forest" | "volcano" | "underwater"` (the set of values that can appear on `data-theme`). - Change `resolveTheme`'s return type to `ResolvedTheme`. The body stays the same: `"system"` → `systemDark ? "dark" : "light"`, everything else passes through. - Update `parseChoice` to also accept `"forest"`, `"volcano"`, `"underwater"` as valid explicit values (anything else still falls back to `"system"`). The implementation is a small list-membership check; keep it as a tuple or `Set` so adding a future theme is one entry.2. **`web/index.html`** (inline pre-paint `<script>`, line 17) — extend the condition that decides whether to use the stored value or fall back to the system preference. Currently it only passes through `"light"` and `"dark"`. Extend it to also pass through `"forest"`, `"volcano"`, `"underwater"`. Keep the inline duplicate (it must not import from the module; it runs before any module loads).3. **`web/src/status/theme.ts`** — no code changes needed. It already calls `resolveTheme(choice, media.matches)` and sets `data-theme` to the result. The widened type flows through automatically. Verify that `ThemeChoice` is imported from `theme-choice.ts` (it is, line 1) so the new members are available in the `stored()` read and `set()` write.### Phase 2 — CSS colour palettes

The structure and token list are fixed.### Phase 3 — UI choice lists

- **Included:** three new dark-variant named themes (forest, volcano, underwater) as explicit `ThemeChoice` values; CSS palette blocks; UI lists in both the View menu and Settings panel; updated pure-function tests; pre-paint script extension. - **Excluded:** a theme editor / custom colour picker; light variants of the new themes; server-side or WebSocket theme awareness; per-theme `prefers-color-scheme` behaviour (the new themes are always their own palette, regardless of OS preference); theming of the terminal beyond what `terminal-panel.ts` already reads from computed CSS variables.

**Decisions**

- All three new themes are **dark variants** (dark-based palettes with a distinct accent hue). No light variants. - "Match system" remains and still follows the OS light/dark preference. The new themes are **explicit**: selecting "forest" always shows the forest palette, regardless of the OS preference. - The theme picker is a **flat list** of all six choices in both the View menu and Settings panel (no grouping). - No server or WebSocket involvement: the theme remains purely page-local (localStorage + CSS attribute + computed CSS values read by the terminal). - The pre-paint script in `index.html` is kept inline (it cannot import from the module; it must run before any module loads) and is updated in lockstep with `parseChoice`/`resolveTheme`.

**Further Considerations**

1. The hex palettes above are starting points. The implementer should verify WCAG AA contrast ratios for `--text` on `--bg` and `--accent` on `--bg` for each theme, and adjust if any pair falls below 4.5:1. - If a fourth theme is added in the future, the pattern is: add the string to `ThemeChoice`, extend the membership check in `parseChoice`, add a `:root[data-theme=…]` block in `tokens.css`, and add an entry to both `choices` arrays. The pre-paint script and `resolveTheme` need no further changes once the pattern is established.
